# Contribution Guide

Thank you for your interest in contributing to this research repository. This project is community-maintained and has a strictly academic and proof-of-concept focus on network architecture and authentication protocols used in captive portals.

## Contribution Workflow

To maintain the integrity and quality of the repository, we ask all contributors to follow the standard Fork and Pull Request workflow:

1. **Fork:** Create a fork of this repository under your personal account.
2. **Create a Branch:** Create a dedicated branch for your contribution from the `main` branch. Use a descriptive naming convention (for example: `feat/linux-mac-documentation`, `fix/osi-theory-correction`).
3. **Development:** Make the proposed changes. Ensure that the Markdown formatting complies with the repository standards.
4. **Commits:** Write clear and concise commit messages describing the technical changes made.
5. **Pull Request:** Submit a Pull Request (PR) targeting the `main` branch of the original repository.

## Documentation Standards

If you would like to add a new implementation procedure or expand the technical foundation, make sure your contribution meets the following criteria:

- **Technical Accuracy:** Use precise terminology consistent with network architecture.
- **Neutrality:** Maintain an objective and informative tone.
- **Formatting:** Every document must be properly structured using Markdown syntax, including hierarchical headings, lists, and code blocks where appropriate.
- **Visual Evidence:** If you contribute a new tutorial for an operating system, you must include the exact configuration paths. Visual references are accepted as long as they do not contain any personally identifiable information.

## Code of Conduct and Legal Considerations

By contributing to this project, you agree that the submitted content is intended exclusively for research and educational purposes.

Pull Requests containing the following will not be accepted:

- Automated scripts, executables, or source code designed for denial-of-service attacks or destructive exploitation.
- Modifications that promote unauthorized access to private networks.
- Content that infringes on third-party copyrights.

All contributions will be reviewed by the project maintainers before being merged.
